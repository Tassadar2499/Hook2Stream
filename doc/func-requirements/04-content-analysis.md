# 04. Анализ музыкального и визуального контента

## Назначение и границы

Документ определяет функциональные требования к настройке анализа, извлечению музыкальных, текстовых и визуальных признаков, формированию объяснимых и разнообразных кандидатов, а также к ручным и обучающим контурам. Приоритеты соответствуют этапам `P0 / Core MVP`, `P1 / V1` и `P2 / V2` исходного плана.

## Функциональные требования

### FR-ANL-001 — Настройка целей анализа

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий), [§ 8.5 «Создание проекта»](../base/AI_Content_Factory_SaaS_Plan.md#85-создание-проекта)
- **Требование:** Система должна до запуска анализа позволять пользователю выбрать целевые типы моментов, диапазон длительности клипа и количество кандидатов.
- **Правила и предусловия:**
  - Доступные в Core MVP типы: `chorus`, `lyric`, `riff/solo`, `visual`.
  - Для нового проекта начальный диапазон длительности candidates составляет 15–45 секунд; пользователь может изменить его внутри `CFG-CANDIDATE-MIN-DURATION` и `CFG-CANDIDATE-MAX-DURATION`, а platform preset может дополнительно сузить диапазон.
  - До запуска должны быть выполнены rights gate из `FR-RGT-002` и entitlement check из `FR-BIL-005`.
  - Эффективное количество кандидатов не должно превышать entitlement текущего workspace, заданный параметром `CFG-ENTITLEMENT-CANDIDATE-PREVIEWS` по `DEC-004`; применённый лимит должен быть показан до запуска.
  - Точные границы пользовательского диапазона длительности задаются параметрами `CFG-CANDIDATE-MIN-DURATION` и `CFG-CANDIDATE-MAX-DURATION`; их значения фиксируются решением `DEC-002` в README требований.
- **Критерии приёмки:**
  - **AC-01 — Сохранение валидной конфигурации**
    - **Дано:** пользователь создал проект и загрузил исходное видео;
    - **Когда:** пользователь выбирает типы `chorus` и `visual`, допустимый диапазон длительности и доступное по entitlement количество кандидатов;
    - **Тогда:** система сохраняет конфигурацию в проекте и использует её при запуске анализа.
  - **AC-02 — Ограничение по entitlement**
    - **Дано:** выбранное количество кандидатов превышает entitlement workspace;
    - **Когда:** пользователь пытается запустить анализ;
    - **Тогда:** система не запускает анализ, показывает допустимое количество и предлагает скорректировать конфигурацию.
  - **AC-03 — Диапазон по умолчанию**
    - **Дано:** пользователь создаёт новый проект и ещё не изменял длительность candidates;
    - **Когда:** система показывает настройки анализа;
    - **Тогда:** выбран диапазон 15–45 секунд, ограниченный более строгим применимым platform preset при его наличии.
- **Связанные FR:** FR-RGT-002, FR-ANL-008, FR-ANL-012, FR-ANL-014, FR-BIL-005

### FR-ANL-002 — Определение структуры песни

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна анализировать аудиодорожку и формировать временную разметку музыкальных секций `intro`, `verse`, `chorus`, `bridge/drop`, `solo` и `outro` на основе повторов, энергии и музыкальных границ.
- **Правила и предусловия:**
  - Анализ выполняется после успешного извлечения аудиодорожки из исходного видео.
  - Для каждой найденной секции должны сохраняться тип, время начала и время окончания.
  - Отсутствующий в конкретной композиции тип секции не должен создаваться искусственно.
- **Критерии приёмки:**
  - **AC-01 — Сохранение найденных секций**
    - **Дано:** исходное видео содержит пригодную для анализа аудиодорожку;
    - **Когда:** этап музыкального анализа завершается успешно;
    - **Тогда:** система сохраняет найденные секции с типами и непротиворечивыми временными границами внутри длительности исходника.
  - **AC-02 — Необнаруженная секция**
    - **Дано:** анализ не обнаружил секцию типа `solo` с достаточной уверенностью;
    - **Когда:** система сохраняет результат анализа;
    - **Тогда:** система не добавляет фиктивную секцию `solo`, а остальные найденные секции остаются доступными для формирования кандидатов.
- **Связанные FR:** FR-ANL-006, FR-ANL-009, FR-ANL-011

### FR-ANL-003 — Анализ текста песни

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна анализировать доступный текст песни и его тайминги, выделять сильные строки, повторы и завершённые смысловые фразы, а также снижать оценку сегментов, обрывающих слово или строку.
- **Правила и предусловия:**
  - Источником может быть вставленный текст после выравнивания, SRT/VTT или результат автоматического распознавания.
  - Анализ должен использовать актуальную сохранённую редакцию текста и таймингов.
- **Критерии приёмки:**
  - **AC-01 — Выделение законченной фразы**
    - **Дано:** у проекта есть текст с таймингами и повторяющаяся законченная строка;
    - **Когда:** система выполняет анализ lyrics;
    - **Тогда:** система сохраняет строку как lyric-признак с временными границами, пригодными для оценки кандидатов.
  - **AC-02 — Штраф за обрыв текста**
    - **Дано:** один сегмент заканчивается внутри слова или строки, а другой охватывает законченную фразу;
    - **Когда:** система рассчитывает lyric-признаки этих сегментов;
    - **Тогда:** сегмент с обрывом получает `text_cut_penalty`, учитываемый гибридным scorer.
- **Связанные FR:** FR-LYR-010, FR-ANL-006, FR-ANL-009, FR-EDT-004, FR-EDT-008

### FR-ANL-004 — Анализ без текста песни

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.3 «Права, текст песни и соответствие требованиям»](../base/AI_Content_Factory_SaaS_Plan.md#63-права-текст-песни-и-соответствие-требованиям), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна позволять выполнить анализ без текста песни и формировать кандидатов на основе музыкальных и визуальных признаков.
- **Правила и предусловия:**
  - Режим предназначен в том числе для instrumental, riff/solo и visual clips.
  - Отсутствие текста не должно считаться ошибкой анализа.
  - Lyric-признаки и объяснения, зависящие от текста, в этом режиме не формируются.
- **Критерии приёмки:**
  - **AC-01 — Успешный instrumental-анализ**
    - **Дано:** проект содержит исходное видео с инструментальной аудиодорожкой и не содержит lyrics/transcript;
    - **Когда:** пользователь выбирает продолжение без текста и запускает анализ;
    - **Тогда:** система анализирует музыкальную структуру и визуальный ряд и формирует кандидатов без lyric-признаков.
  - **AC-02 — Отсутствие ложной ошибки**
    - **Дано:** анализ без текста завершил музыкальные и визуальные этапы успешно;
    - **Когда:** система определяет итоговое состояние analysis job;
    - **Тогда:** система не переводит job в `Failed` только из-за отсутствующего текста.
- **Связанные FR:** FR-LYR-009, FR-ANL-002, FR-ANL-005, FR-ANL-006, FR-ANL-009

### FR-ANL-005 — Анализ сцен и пригодности к вертикальному кадру

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна анализировать границы кадров, визуальную активность, резкие переходы и пригодность временных сегментов к вертикальной композиции.
- **Правила и предусловия:**
  - Анализ выполняется по подготовленному proxy или исходному asset, сохраняющему временное соответствие оригиналу.
  - Для каждого timestamped segment должны быть доступны visual-признаки, используемые scorer.
- **Критерии приёмки:**
  - **AC-01 — Выделение визуальной кульминации**
    - **Дано:** в исходном видео есть сегмент с заметным ростом визуальной активности и сменой сцен;
    - **Когда:** система завершает анализ сцен;
    - **Тогда:** система сохраняет для сегмента признаки visual activity и shot boundaries с корректными таймкодами.
  - **AC-02 — Риск вертикальной композиции**
    - **Дано:** важные объекты широкого кадра не помещаются в стандартную область вертикального crop;
    - **Когда:** система оценивает vertical fit сегмента;
    - **Тогда:** система снижает признак vertical fit или помечает необходимость проверки crop для последующего показа пользователю.
- **Связанные FR:** FR-ANL-006, FR-ANL-009, FR-EDT-005, FR-EDT-006

### FR-ANL-006 — Гибридная оценка timestamped segments

- **Этап:** P0 / Core MVP
- **Актор:** Система анализа
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 9.5 «Как искать сильные моменты»](../base/AI_Content_Factory_SaaS_Plan.md#95-как-искать-сильные-моменты)
- **Требование:** Система должна рассчитывать итоговую оценку подготовленных timestamped segments по музыкальным, энергетическим, текстовым, визуальным, композиционным и граничным признакам с учётом штрафов за перекрытие и обрыв текста.
- **Правила и предусловия:**
  - Scorer должен учитывать доступные признаки `musical_section`, `energy_change`, `lyric_hook`, `visual_activity`, `vertical_fit`, `clean_start_end`, `overlap_penalty` и `text_cut_penalty`.
  - Недоступный признак не должен приводить к ошибке всего scorer.
  - LLM может ранжировать только заранее подготовленные timestamped segments и объяснять выбор; LLM не должен создавать таймкоды из необработанного видео.
  - Результат не должен называться или представляться как `viral score`.
- **Критерии приёмки:**
  - **AC-01 — Расчёт по доступным признакам**
    - **Дано:** для сегмента рассчитаны музыкальные, текстовые и визуальные признаки;
    - **Когда:** гибридный scorer обрабатывает сегмент;
    - **Тогда:** система сохраняет итоговую оценку и вклад доступных групп признаков для последующего объяснения.
  - **AC-02 — Запрет вымышленных таймкодов**
    - **Дано:** внешний LLM возвращает интервал, отсутствующий среди переданных timestamped segments;
    - **Когда:** система валидирует ответ LLM;
    - **Тогда:** система отклоняет этот интервал и не создаёт на его основе кандидата.
- **Связанные FR:** FR-ANL-002, FR-ANL-003, FR-ANL-005, FR-ANL-007, FR-ANL-009

### FR-ANL-007 — Разнообразие набора кандидатов

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 9.5 «Как искать сильные моменты»](../base/AI_Content_Factory_SaaS_Plan.md#95-как-искать-сильные-моменты)
- **Требование:** Система должна после первичного scoring выбирать итоговый набор кандидатов с ограничением чрезмерного временного перекрытия и с покрытием разных запрошенных типов моментов.
- **Правила и предусловия:**
  - Допустимая доля перекрытия задаётся параметром `CFG-CANDIDATE-MAX-OVERLAP`; значение фиксируется решением `DEC-002` в README требований.
  - Если исходный материал не позволяет удовлетворить diversity-правила полностью, система должна вернуть доступный неповторяющийся набор и явно показать, что кандидатов меньше запрошенного.
- **Критерии приёмки:**
  - **AC-01 — Исключение чрезмерно похожих результатов**
    - **Дано:** два высоко оценённых сегмента перекрываются больше `CFG-CANDIDATE-MAX-OVERLAP`;
    - **Когда:** система выполняет diversity selection;
    - **Тогда:** система не включает оба сегмента в итоговый набор, если доступен сопоставимый неперекрывающийся сегмент.
  - **AC-02 — Покрытие разных типов**
    - **Дано:** пользователь запросил `chorus` и `visual`, и для обоих типов есть валидные сегменты;
    - **Когда:** система формирует итоговый набор;
    - **Тогда:** итоговый набор содержит кандидатов обоих запрошенных типов, а не только варианты одного момента.
- **Связанные FR:** FR-ANL-001, FR-ANL-006, FR-ANL-008, FR-ANL-012

### FR-ANL-008 — Формирование набора кандидатов Core MVP

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна для обычной Core MVP campaign формировать от 6 до 10 валидных кандидатов в пределах выбранной пользователем конфигурации и entitlement.
- **Правила и предусловия:**
  - Каждый кандидат должен иметь уникальный идентификатор, временные границы, длительность, тип, оценку и ссылку на analysis job.
  - Trial или иной тариф может устанавливать меньший лимит previews; эффективный лимит должен быть известен пользователю до запуска.
  - Если валидных сегментов меньше эффективного лимита, система сохраняет все доступные сегменты и фиксирует partial success с причиной.
- **Критерии приёмки:**
  - **AC-01 — Обычный результат кампании**
    - **Дано:** entitlement разрешает 10 кандидатов и исходник содержит не менее 10 валидных разнообразных сегментов;
    - **Когда:** пользователь запрашивает 10 кандидатов и анализ завершается;
    - **Тогда:** система сохраняет 10 кандидатов, удовлетворяющих правилам diversity.
  - **AC-02 — Недостаточно валидных сегментов**
    - **Дано:** после scoring и diversity selection найдено меньше запрошенного количества валидных сегментов;
    - **Когда:** система завершает формирование набора;
    - **Тогда:** система сохраняет все валидные кандидаты, не создаёт фиктивные и сообщает причину уменьшенного результата.
- **Связанные FR:** FR-ANL-001, FR-ANL-007, FR-ANL-009, FR-ANL-015, FR-ANL-016

### FR-ANL-009 — Объяснение выбора кандидата

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 8.7 «Candidate Review»](../base/AI_Content_Factory_SaaS_Plan.md#87-candidate-review)
- **Требование:** Система должна для каждого автоматически сформированного кандидата показывать понятное объяснение его выбора, основанное на сохранённых признаках анализа.
- **Правила и предусловия:**
  - Объяснение должно отражать фактически повлиявшие признаки, например: начало припева, рост энергии, сильная строка или визуальная кульминация.
  - Объяснение не должно содержать неподтверждённый признак или обещание performance.
- **Критерии приёмки:**
  - **AC-01 — Трассируемое объяснение**
    - **Дано:** кандидат выбран благодаря признакам `chorus`, `energy_change` и `lyric_hook`;
    - **Когда:** пользователь открывает карточку кандидата;
    - **Тогда:** система показывает объяснение, отражающее эти признаки.
  - **AC-02 — Отсутствие псевдообъяснения**
    - **Дано:** scorer не сохранил lyric-признак для кандидата;
    - **Когда:** пользователь просматривает объяснение;
    - **Тогда:** система не упоминает сильную строку и не заменяет объяснение псевдоточным `viral score`.
- **Связанные FR:** FR-ANL-003, FR-ANL-005, FR-ANL-006, FR-ANL-015, FR-EDT-001

### FR-ANL-010 — Создание ручного кандидата

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна позволять пользователю создать кандидата вручную, выбрав произвольный валидный временной участок исходного видео.
- **Правила и предусловия:**
  - Временные границы должны находиться внутри исходного asset и образовывать положительную длительность.
  - Длительность должна соответствовать текущим параметрам допустимого клипа либо система должна потребовать её исправить до сохранения.
  - Ручной кандидат должен быть явно отличим от автоматически предложенного и не обязан иметь AI-confidence.
- **Критерии приёмки:**
  - **AC-01 — Сохранение ручного участка**
    - **Дано:** пользователь открыл timeline успешно обработанного проекта;
    - **Когда:** пользователь задаёт валидные in/out границы и сохраняет ручной кандидат;
    - **Тогда:** система создаёт кандидата с указанными таймкодами, источником `manual` и делает его доступным в Candidate Review.
  - **AC-02 — Невалидные границы**
    - **Дано:** выбранный out предшествует in либо выходит за длительность исходника;
    - **Когда:** пользователь пытается сохранить ручной кандидат;
    - **Тогда:** система не создаёт кандидата и показывает, какие границы необходимо исправить.
- **Связанные FR:** FR-ANL-001, FR-EDT-001, FR-EDT-004

- **Требование:** Система должна позволять пользователю исправить границы и типы секций песни и использовать сохранённую корректировку как вход для повторной генерации кандидатов по `FR-ANL-019`.
- **Правила и предусловия:**
  - Корректируемые секции должны оставаться внутри длительности исходника.

  - **AC-02 — Сохранность существующей версии клипа**
    - **Дано:** до повторной генерации из кандидата уже создана immutable ClipVersion;
    - **Когда:** новая ревизия анализа заменяет набор активных кандидатов;
    - **Тогда:** существующая ClipVersion продолжает ссылаться на прежние временные границы и не изменяется.
- **Связанные FR:** FR-ANL-002, FR-ANL-008, FR-ANL-019, FR-EDT-010, FR-EXP-008

### FR-ANL-012 — Формирование кандидатов по clip recipes

    - **Дано:** проект обрабатывается без текста и выбран также `lyric hook`;

    - **Тогда:** система пропускает `lyric hook` с понятной причиной и продолжает формирование музыкальных и визуальных кандидатов.

### FR-ANL-013 — Учёт предпочтений артиста

- **Этап:** P2 / V2
- **Актор:** Пользователь
- **Источник:** [§ 6.4 «Музыкальный и визуальный анализ»](../base/AI_Content_Factory_SaaS_Plan.md#64-музыкальный-и-визуальный-анализ), [§ 6.8 «Аналитика и learning loop»](../base/AI_Content_Factory_SaaS_Plan.md#68-аналитика-и-learning-loop)
- **Требование:** Система должна при ранжировании кандидатов учитывать накопленные решения `Selected`/`Rejected` и доступные фактические performance-метрики конкретного артиста, сохраняя возможность пользователя изменить результат вручную.
- **Правила и предусловия:**
  - Персонализация применяется только к данным того же артиста в разрешённом workspace-контексте.
  - Рекомендация должна сопровождаться причиной, указывающей, какие исторические признаки повлияли на неё.

  - **AC-01 — Персонализированное ранжирование**
    - **Дано:** у артиста накоплены решения и performance-метрики по прежним кампаниям;
    - **Когда:** система ранжирует кандидатов нового релиза;
    - **Тогда:** система учитывает эти данные и показывает причину персонализированной рекомендации.
  - **AC-02 — Изоляция между артистами**
    - **Дано:** workspace содержит несколько артистов с разной историей;
    - **Когда:** система ранжирует кандидатов артиста A;
    - **Тогда:** система не использует историю артиста B как историю артиста A.
- **Связанные FR:** FR-ANL-006, FR-ANL-009, FR-EDT-002, FR-MET-002, FR-MET-009

### FR-ANL-014 — Состояние и прогресс analysis job

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 8.6 «Processing»](../base/AI_Content_Factory_SaaS_Plan.md#86-processing), [§ 9.3 «Состояния»](../base/AI_Content_Factory_SaaS_Plan.md#93-состояния), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна выполнять анализ как durable job, показывать его текущее состояние и пользовательскую стадию и продолжать обработку после закрытия страницы.
- **Правила и предусловия:**
  - Job использует состояния `Queued`, `Running`, `Succeeded`, `Failed`, `Cancelled`.
  - Пользователю показываются как минимум стадии проверки файла, сопоставления аудио и lyrics, анализа структуры/сцен и подготовки previews.
  - Закрытие страницы не должно отменять job.
  - Терминальное состояние должно сопровождаться результатом или следующим доступным действием.
- **Критерии приёмки:**
  - **AC-01 — Продолжение после закрытия страницы**
    - **Дано:** analysis job находится в `Running`;
    - **Когда:** пользователь закрывает и позднее повторно открывает страницу проекта;
    - **Тогда:** система продолжает тот же job и показывает его актуальные состояние и стадию.
  - **AC-02 — Обновление стадий**
    - **Дано:** job последовательно выполняет сопоставление lyrics, анализ структуры/сцен и подготовку previews;
    - **Когда:** завершается очередная стадия;
    - **Тогда:** система сохраняет progress и показывает следующую пользовательскую стадию без запуска нового job.
- **Связанные FR:** FR-ANL-008, FR-ANL-016, FR-ANL-017, FR-EDT-001

### FR-ANL-015 — Confidence и предупреждения кандидата

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 8.7 «Candidate Review»](../base/AI_Content_Factory_SaaS_Plan.md#87-candidate-review), [§ 6.3 «Права, текст песни и соответствие требованиям»](../base/AI_Content_Factory_SaaS_Plan.md#63-права-текст-песни-и-соответствие-требованиям)
- **Требование:** Система должна для каждого автоматически сформированного кандидата показывать уровень confidence и предупреждать о необходимости проверить crop или текст при соответствующем риске.
- **Правила и предусловия:**
  - Шкала candidate confidence задаётся `CFG-CANDIDATE-CONFIDENCE-LEVELS` по `DEC-002`.
  - Порог low confidence текста задаётся `CFG-LYRICS-LOW-CONFIDENCE-THRESHOLD` по `DEC-011`.
  - Confidence не должен подаваться как вероятность вирусности.
- **Критерии приёмки:**
  - **AC-01 — Низкая уверенность текста**
    - **Дано:** confidence текста ниже `CFG-LYRICS-LOW-CONFIDENCE-THRESHOLD`;
    - **Когда:** пользователь просматривает кандидата;
    - **Тогда:** система показывает уровень confidence и предупреждение о проверке текста.
  - **AC-02 — Риск кадрирования**
    - **Дано:** visual analysis пометил vertical fit кандидата как требующий проверки;
    - **Когда:** пользователь просматривает кандидата;
    - **Тогда:** система показывает crop warning и не маркирует клип как гарантированно готовый.
- **Связанные FR:** FR-LYR-005, FR-ANL-005, FR-ANL-009, FR-EDT-001

### FR-ANL-016 — Сохранение результатов при частичном успехе

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 8.6 «Processing»](../base/AI_Content_Factory_SaaS_Plan.md#86-processing), [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp)
- **Требование:** Система должна сохранять и предоставлять пользователю успешно подготовленные кандидаты и previews, если независимая часть анализа завершилась ошибкой.
- **Правила и предусловия:**
  - Ошибка одного кандидата или preview не должна удалять остальные результаты проекта.
  - Система должна явно различать полный успех, частичный успех и отсутствие пригодного результата.
- **Критерии приёмки:**
  - **AC-01 — Один сбойный preview**
    - **Дано:** previews нескольких кандидатов готовы, а один независимый preview завершился ошибкой;
    - **Когда:** система завершает текущую попытку анализа;
    - **Тогда:** готовые кандидаты доступны для review, а сбойный элемент показан отдельно с доступным следующим действием.
  - **AC-02 — Нет пригодного результата**
    - **Дано:** ни один кандидат не прошёл обязательную подготовку;
    - **Когда:** analysis job завершается;
    - **Тогда:** система не показывает ложный partial success и сообщает, почему review недоступен.
- **Связанные FR:** FR-PRJ-017, FR-ANL-008, FR-ANL-014, FR-ANL-017, FR-EDT-001

### FR-ANL-017 — Идемпотентный restart и retry анализа

- **Этап:** P0 / Core MVP
- **Актор:** Фоновый обработчик
- **Источник:** [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline), [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp)
- **Требование:** Система должна идемпотентно возобновлять или повторять analysis job после restart, recoverable failure или duplicate delivery без повторного подтверждённого результата и двойного списания.
- **Правила и предусловия:**
  - Уже подтверждённая стадия не должна повторять side effects при возобновлении.
  - Retry создаёт новую попытку той же логической операции и сохраняет трассировку попыток.
- **Критерии приёмки:**
  - **AC-01 — Restart во время scoring**
    - **Дано:** job завершил media preparation, а worker перезапущен во время scoring;
    - **Когда:** обработчик возобновляет job;
    - **Тогда:** система продолжает с безопасной стадии и не создаёт вторые media assets или usage operation.
  - **AC-02 — Duplicate delivery**
    - **Дано:** команда завершённой стадии доставлена повторно;
    - **Когда:** система проверяет idempotency key;
    - **Тогда:** система переиспользует подтверждённый результат и не выполняет стадию повторно.
- **Связанные FR:** FR-ANL-014, FR-ANL-016, FR-BIL-004

### FR-ANL-018 — Отмена analysis job

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 8.10 «Обязательные UX-состояния»](../base/AI_Content_Factory_SaaS_Plan.md#810-обязательные-ux-состояния), [§ 10.2 «Эпики Core MVP»](../base/AI_Content_Factory_SaaS_Plan.md#102-эпики-core-mvp)
- **Требование:** Система должна позволять пользователю отменить доступный analysis job в состоянии `Queued` или `Running` и показать его фактическое терминальное состояние.
- **Правила и предусловия:**
  - После принятия отмены система не должна запускать новые стадии job.
  - Уже зафиксированные независимые результаты сохраняются по правилам partial success, а незавершённая работа не выдаётся как успешная.
  - Usage reservation закрывается по фактически подтверждённому результату; гонка отмены с завершением не должна приводить к двойному списанию или двум терминальным исходам.
  - Для уже терминального job система возвращает его фактическое состояние вместо ложного подтверждения отмены.
- **Критерии приёмки:**
  - **AC-01 — Отмена выполняющегося анализа**
    - **Дано:** analysis job находится в `Running` и ещё может быть остановлен;
    - **Когда:** пользователь подтверждает отмену;
    - **Тогда:** система прекращает запуск новых стадий, переводит job в `Cancelled`, сохраняет допустимые частичные результаты и корректно закрывает usage reservation.
  - **AC-02 — Гонка отмены с завершением**
    - **Дано:** запрос отмены и завершение последней стадии происходят одновременно;
    - **Когда:** система фиксирует результат логической операции;
    - **Тогда:** job получает ровно одно фактическое терминальное состояние, а результат и usage учитываются не более одного раза.
- **Связанные FR:** FR-ANL-014, FR-ANL-016, FR-ANL-017, FR-BIL-003, FR-BIL-004

### FR-ANL-019 — Повторная генерация кандидатов

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 10.2, Epic E6 «Analysis и candidates»](../base/AI_Content_Factory_SaaS_Plan.md#102-эпики-core-mvp), [§ 8.7 «Candidate Review»](../base/AI_Content_Factory_SaaS_Plan.md#87-candidate-review)

**Требование:** Система должна позволять пользователю повторно сформировать candidates из текущих подтверждённых inputs проекта без повторного upload или ingest исходного media.

**Правила и предусловия:**

- Regeneration использует доступные подготовленные media features, актуальную подтверждённую transcript revision, текущие recipes/settings и применимые manual candidates.
- Операция создаёт новую analysis/candidate revision, не изменяет прежние immutable `ClipVersion` и сохраняет трассировку исходной revision.
- Перенос состояний `Selected`/`Rejected` определяется `CFG-CANDIDATE-REGENERATION-FEEDBACK` по `DEC-002`; система не переносит feedback молча вопреки активному правилу.
- До запуска показывается применимый usage, выполняется reservation и проверяются те же права/entitlements, что для analysis.
- P1-корректировка музыкальной структуры из `FR-ANL-011` является дополнительным возможным input, но не нужна для базового P0 regenerate.

**Критерии приёмки:**

- **AC-01**
  - **Дано:** у проекта есть завершённая candidate revision и доступные подготовленные media features;
  - **Когда:** пользователь подтверждает regenerate без изменения source;
  - **Тогда:** система создаёт новую independently identified candidate revision из текущих inputs, не повторяет upload/ingest и показывает её результаты отдельно от прежней.
- **AC-02**
  - **Дано:** из прежней candidate revision уже создана immutable `ClipVersion`;
  - **Когда:** regeneration завершается и новая revision становится активной для review;
  - **Тогда:** прежняя `ClipVersion` и её временные границы не изменяются, а feedback переносится или сбрасывается строго по активному `CFG-CANDIDATE-REGENERATION-FEEDBACK`.

**Связанные FR:** FR-RGT-002, FR-ANL-001, FR-ANL-008, FR-ANL-011, FR-ANL-017, FR-EDT-002, FR-EXP-008, FR-BIL-002
