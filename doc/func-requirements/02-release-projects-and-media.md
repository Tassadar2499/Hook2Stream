# Функциональные требования: проекты релиза и media assets

Документ описывает проект релиза, загрузку и проверку исходного видео, browser-assets, состояния обработки и управление media lifecycle. Значения технических лимитов определяются конфигурацией и открытыми решениями, а не этим документом.

## 1. P0 / Core MVP

### FR-PRJ-001 — Создание проекта релиза

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий), [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 8.5 «Создание проекта»](../base/AI_Content_Factory_SaaS_Plan.md#85-создание-проекта)

**Требование:** Система должна позволять пользователю создать `Draft` проекта релиза в доступном workspace и провести его через возобновляемый трёхшаговый мастер `Видео → Трек и права → Lyrics и настройки результата`.

**Правила и предусловия:**

- Порядок шагов фиксирован, но пользователь может вернуться к завершённому шагу без потери уже сохранённых данных.
- Состояние текущего шага и введённые данные сохраняются в `Draft`, чтобы мастер можно было продолжить после закрытия страницы.
- Обязательность конкретных данных определяется профильными FR: валидный source и подтверждение прав обязательны до analysis, а lyrics можно предоставить, получить через ASR либо явно пропустить по `FR-LYR-009`.
- Defaults настроек результата не превращают необязательные поля базового плана в блокирующие.

**Критерии приёмки:**

- **AC-01:** **Дано** аутентифицированный пользователь имеет доступ к workspace, **когда** он начинает мастер нового проекта, **тогда** система сохраняет в этом workspace `Draft`, возвращает его ID и открывает первый шаг «Видео».
- **AC-02:** **Дано** пользователь не имеет доступа к указанному workspace, **когда** он пытается создать в нём проект, **тогда** система отклоняет операцию и не создаёт проект.
- **AC-03:** **Дано** пользователь сохранил видео и часть данных шага «Трек и права», **когда** он закрывает страницу и позднее открывает этот `Draft`, **тогда** система восстанавливает сохранённые данные и текущий шаг без повторного upload.
- **AC-04:** **Дано** source валиден, права подтверждены, а lyrics отсутствуют, **когда** пользователь на третьем шаге явно выбирает продолжение без текста и подтверждает допустимые defaults результата, **тогда** система завершает мастер и разрешает analysis без требования необязательных lyrics.
- **AC-05:** **Дано** пользователь проходит новый `Draft`, **когда** он завершает каждый шаг, **тогда** система предлагает шаги в порядке «Видео», «Трек и права», «Lyrics и настройки результата» и не разрешает analysis до валидного source и обязательного подтверждения прав.

**Связанные FR:** `FR-ACC-005`, `FR-ACC-006`, `FR-PRJ-002`, `FR-PRJ-007`, `FR-RGT-001`, `FR-LYR-001`, `FR-LYR-009`.

### FR-PRJ-002 — Метаданные релиза

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий), [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека)

**Требование:** Система должна позволять пользователю сохранять и изменять в проекте исполнителя, название трека, язык, жанр, дату релиза, CTA, smart-link и internal notes.

**Правила и предусловия:**

- Применимость и обязательность отдельных полей задаются сценарием проекта и не должны превращать необязательные данные из базового плана в блокирующие.
- Internal notes не являются platform metadata и не передаются во внешний export или публикацию без отдельного явного действия.

**Критерии приёмки:**

- **AC-01:** **Дано** пользователь редактирует доступный проект, **когда** он сохраняет допустимые метаданные релиза, **тогда** система связывает значения с этим проектом и возвращает их при следующем открытии.
- **AC-02:** **Дано** проект содержит internal notes, **когда** система формирует platform copy или данные публикации, **тогда** internal notes не включаются в результат автоматически.

**Связанные FR:** `FR-PRJ-001`, `FR-ACC-011`, `FR-RGT-001`, `FR-LYR-001`.

### FR-PRJ-003 — Связность данных проекта

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 9.2 «Основные доменные сущности»](../base/AI_Content_Factory_SaaS_Plan.md#92-основные-доменные-сущности)

**Требование:** Система должна связывать в одном проекте исходные и производные assets, метаданные релиза, lyrics/transcript, candidates, clip versions, copy и exports без смешения с другими проектами.

**Критерии приёмки:**

- **AC-01:** **Дано** в проекте созданы исходник и производные результаты, **когда** пользователь открывает проект, **тогда** система возвращает связанные с ним данные и их актуальные состояния.
- **AC-02:** **Дано** существуют данные двух проектов одного workspace, **когда** пользователь открывает один из проектов, **тогда** система не включает в него assets, candidates, versions, copy или exports другого проекта.

**Связанные FR:** `FR-ACC-006`, `FR-ANL-001`, `FR-EDT-001`.

### FR-PRJ-004 — Просмотр списка проектов

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 8.4 «Dashboard»](../base/AI_Content_Factory_SaaS_Plan.md#84-dashboard)

**Требование:** Система должна показывать пользователю доступные ему последние проекты с thumbnail, треком, датой релиза, числом доступных candidates и готовых clips и текущим статусом.

**Критерии приёмки:**

- **AC-02:** **Дано** в workspace ещё нет проектов, **когда** пользователь открывает список, **тогда** система показывает first-run состояние и действие создания проекта вместо пустой технической таблицы.

**Связанные FR:** `FR-ACC-006`, `FR-PRJ-001`, `FR-PRJ-006`.

### FR-PRJ-005 — Переименование и архивирование проекта

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека)

**Требование:** Система должна позволять пользователю переименовать доступный проект и перевести его в состояние `Archived` без удаления project data.

**Правила и предусловия:**

- Архивировать можно проект в любом non-deleted состоянии, если у него нет активных upload/analysis/render/publication jobs, включая `Processing` с terminal failed/cancelled job.
- При наличии активного job система требует дождаться завершения либо выполнить допустимую отмену до архивирования.

**Критерии приёмки:**

- **AC-01:** **Дано** существует доступный проект, **когда** пользователь сохраняет допустимое новое имя, **тогда** система изменяет имя, не меняя ID и связанные данные проекта.
- **AC-02:** **Дано** non-deleted проект не имеет активных jobs, в том числе находится в `Processing` после terminal failure, **когда** пользователь архивирует его, **тогда** система присваивает состояние `Archived`, исключает проект из активного рабочего списка и сохраняет его данные согласно retention policy.

**Связанные FR:** `FR-PRJ-006`, `FR-PRJ-018`.

### FR-PRJ-006 — Состояния проекта

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 9.3 «Состояния»](../base/AI_Content_Factory_SaaS_Plan.md#93-состояния)

**Требование:** Система должна вычислять и показывать агрегированное состояние проекта из канонического набора `Draft`, `Uploading`, `Processing`, `Review`, `Ready`, `Archived`, не подменяя им состояния отдельных jobs и clips.

**Правила и предусловия:**

- Ошибка отдельного job не создаёт общее состояние `Failed` для проекта и не уничтожает успешные результаты.
- `Review` доступен при наличии хотя бы одного пригодного candidate, включая candidate из частично успешного анализа; `Ready` — при наличии хотя бы одной immutable `ClipVersion` с валидированным final render.
- Для не удалённого проекта применяется приоритет `Archived → Ready → Review → Uploading → Processing → Draft`.
- Проект с валидным source, terminal `Failed`/`Cancelled` job и без candidates остаётся `Processing`; UI показывает фактическое состояние job и доступное следующее действие.
- Новый running/retry job не понижает проект из `Ready` или `Review`, пока соответствующий готовый результат остаётся доступен.

**Критерии приёмки:**

- **AC-01:** **Дано** проект проходит upload, processing, получает candidate и final render, **когда** меняются фактические результаты, **тогда** система последовательно показывает `Draft`, `Uploading`, `Processing`, `Review` и `Ready`.
- **AC-02:** **Дано** проект имеет валидный final render, а новый job находится в `Running` или `Failed`, **когда** система пересчитывает состояние, **тогда** проект остаётся `Ready`, а состояние нового job показывается отдельно.
- **AC-03:** **Дано** валидный source существует, analysis job завершён `Failed` или `Cancelled` и пригодных candidates нет, **когда** пользователь открывает проект, **тогда** проект остаётся `Processing`, а UI показывает terminal job state и доступный retry либо другое следующее действие.

**Связанные FR:** `FR-PRJ-016`, `FR-PRJ-017`.

### FR-PRJ-007 — Загрузка исходника MP4/MOV

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 8.5 «Создание проекта»](../base/AI_Content_Factory_SaaS_Plan.md#85-создание-проекта)

**Требование:** Система должна позволять пользователю выбрать или перетащить исходный файл MP4 либо MOV и начать его загрузку в доступный проект.

**Критерии приёмки:**

- **AC-01:** **Дано** пользователь открыл доступный проект, **когда** он выбирает MP4 или MOV через file picker либо drag-and-drop, **тогда** система создаёт upload session и переводит проект в `Uploading`.
- **AC-02:** **Дано** пользователь выбирает контейнер, который не заявлен как поддерживаемый, **когда** система может определить это до передачи файла, **тогда** она не запускает upload и показывает поддерживаемые варианты.

**Связанные FR:** `FR-PRJ-006`, `FR-PRJ-008`, `FR-PRJ-011`.

### FR-PRJ-008 — Возобновляемая multipart-загрузка

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)

**Требование:** Система должна загружать исходный файл через resumable multipart upload и позволять продолжить незавершённую действительную upload session без повторной передачи уже подтверждённых частей.

**Критерии приёмки:**

- **AC-01:** **Дано** часть файла успешно загружена и соединение прервалось, **когда** пользователь возобновляет действительную session, **тогда** система продолжает передачу с неподтверждённой части.
- **AC-02:** **Дано** все части подтверждены, **когда** система завершает multipart session, **тогда** создаётся один source asset и запускается его проверка без дублирования уже переданных частей.

**Связанные FR:** `FR-PRJ-007`, `FR-PRJ-010`, `FR-BIL-001`.

### FR-PRJ-009 — Проверка лимитов до списания usage

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 8.5 «Создание проекта»](../base/AI_Content_Factory_SaaS_Plan.md#85-создание-проекта)

**Требование:** Система должна проверить размер и длительность исходника относительно `CFG-MEDIA-MAX-SOURCE-BYTES` и `CFG-MEDIA-MAX-SOURCE-DURATION` и сообщить ожидаемый расход entitlement до окончательного списания usage.

**Правила и предусловия:**

- Конкретные значения и остальные media-ограничения определяются [`DEC-001`](README.md#8-реестр-открытых-решений).
- Отклонённый по лимиту исходник не должен создавать операцию consume; правила reservation/release задаются требованиями billing.

**Критерии приёмки:**

- **AC-01:** **Дано** исходник соответствует активным media-лимитам и у workspace достаточно entitlement, **когда** проверка завершена, **тогда** система показывает применённые границы и ожидаемый расход до подтверждения обработки.
- **AC-02:** **Дано** размер либо длительность исходника превышает активный предел, **когда** система получает достаточные данные для проверки, **тогда** она отклоняет обработку до consume, показывает превышенную границу и освобождает применимую reservation.

**Связанные FR:** `FR-BIL-001`, `FR-BIL-002`, `FR-PRJ-011`.

### FR-PRJ-010 — Отмена незавершённой загрузки

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 10.2, Epic E3 «Upload и media preparation»](../base/AI_Content_Factory_SaaS_Plan.md#102-эпики-core-mvp)

**Требование:** Система должна позволять пользователю отменить активную upload session и прекратить приём её неподтверждённых частей.

**Правила и предусловия:**

- После подтверждённой отмены проект возвращается из `Uploading` в `Draft`, если у него нет другого валидного source asset.
- Неиспользованная usage reservation освобождается по `FR-BIL-003`.
- Если source asset уже атомарно создан до обработки отмены, система возвращает фактический завершённый результат и не удаляет его под видом отменённой session.

**Критерии приёмки:**

- **AC-01:** **Дано** upload session активна и source asset ещё не создан, **когда** пользователь подтверждает отмену, **тогда** система переводит session в отменённое состояние, прекращает дальнейшую передачу, возвращает проект в `Draft` и освобождает неиспользованную reservation.
- **AC-02:** **Дано** upload session отменена, **когда** клиент повторно отправляет часть с её идентификатором, **тогда** система отклоняет часть и не создаёт source asset из отменённой session.

**Связанные FR:** `FR-PRJ-006`, `FR-PRJ-008`, `FR-BIL-001`, `FR-BIL-003`.

### FR-PRJ-011 — Техническая валидация исходника

**Этап:** P0 / Core MVP  
**Актор:** Фоновый обработчик  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)

**Требование:** Система должна после завершения upload проверить фактические контейнер, codec, resolution, frame rate и наличие аудиодорожки посредством media probe до запуска анализа.

**Правила и предусловия:**

- Допустимые значения задаются `CFG-MEDIA-ALLOWED-CONTAINERS`, `CFG-MEDIA-ALLOWED-CODECS`, `CFG-MEDIA-ALLOWED-RESOLUTIONS` и `CFG-MEDIA-ALLOWED-FRAME-RATES` в рамках [`DEC-001`](README.md#8-реестр-открытых-решений).
- Расширение или MIME type, указанные клиентом, не заменяют проверку фактического содержимого.

**Критерии приёмки:**

- **AC-01:** **Дано** загруженный source asset соответствует активным ограничениям и содержит аудиодорожку, **когда** media probe завершается, **тогда** система помечает исходник валидным и разрешает media preparation.
- **AC-02:** **Дано** фактические параметры не соответствуют активным ограничениям либо аудиодорожка отсутствует, **когда** media probe завершается, **тогда** система не запускает анализ, помечает исходник отклонённым с диагностикой согласно `FR-PRJ-012`, освобождает analysis reservation и не создаёт `consume` за незапущенный анализ.

**Связанные FR:** `FR-PRJ-009`, `FR-PRJ-012`, `FR-PRJ-013`, `FR-BIL-003`.

### FR-PRJ-012 — Понятный отказ валидации

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 8.10 «Обязательные UX-состояния»](../base/AI_Content_Factory_SaaS_Plan.md#810-обязательные-ux-состояния)

**Требование:** Система должна при отказе валидации показать пользователю конкретную категорию несовместимости, применённое ограничение и доступное следующее действие.

**Критерии приёмки:**

- **AC-01:** **Дано** media probe обнаружил неподдерживаемый codec, container, resolution, frame rate или отсутствие аудио, **когда** пользователь открывает состояние обработки, **тогда** система показывает соответствующую причину, а не общий unknown error.
- **AC-02:** **Дано** ошибка допускает замену исходника или изменение входных данных, **когда** система показывает отказ, **тогда** интерфейс предоставляет действие возврата к загрузке либо выбора другого файла.

**Связанные FR:** `FR-PRJ-007`, `FR-PRJ-011`.

### FR-PRJ-013 — Создание proxy

**Этап:** P0 / Core MVP  
**Актор:** Фоновый обработчик  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)

**Требование:** Система должна создать из валидного исходника proxy asset для быстрого browser preview, не требующего передачи оригинала в интерфейс.

**Критерии приёмки:**

- **AC-01:** **Дано** исходник прошёл валидацию, **когда** media preparation выполняется успешно, **тогда** система сохраняет proxy и связывает его с исходником и проектом.

### FR-PRJ-017 — Сохранение частичных результатов

**Актор:** Фоновый обработчик  
**Источник:** [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp), [§ 8.6 «Processing»](../base/AI_Content_Factory_SaaS_Plan.md#86-processing)

**Требование:** Система должна сохранять успешно подготовленные результаты проекта при partial success и не удалять их из-за сбоя другого candidate, render или media job.

**Критерии приёмки:**

- **AC-02:** **Дано** после partial success доступен хотя бы один candidate для review, **когда** пользователь открывает проект, **тогда** система позволяет работать с готовым candidate и предлагает retry только для восстановимой неуспешной операции.

**Связанные FR:** `FR-PRJ-006`, `FR-PRJ-016`, `FR-ANL-014`.

### FR-PRJ-018 — Удаление проекта и media assets

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 6.2 «Проекты релиза и медиатека»](../base/AI_Content_Factory_SaaS_Plan.md#62-проекты-релиза-и-медиатека), [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp)

**Требование:** Система должна по подтверждённому запросу пользователя немедленно логически закрыть доступ к проекту и его удаляемым assets, а затем физически удалить их асинхронно в пределах `CFG-DELETION-SLA` с учётом `CFG-RETENTION-*`.

**Правила и предусловия:**

- Значения retention и SLA определяются [`DEC-003`](README.md#8-реестр-открытых-решений).
- Архивирование по `FR-PRJ-005` не является удалением.
- После logical delete система запрещает запуск новых jobs, запрашивает отмену активных upload/analysis/render операций и блокирует dispatch ещё не отправленных scheduled publications.
- Если площадка уже приняла `PlatformNative` schedule удаляемого проекта, система немедленно создаёт обязательную attempt его platform cancel/delete по `FR-PUB-022`; logical delete закрывает локальный доступ, но не помечает внешнее расписание отменённым до подтверждения площадки.
- Logical delete немедленно отзывает или делает недействительными ранее выданные download URLs и share/review links; каждый последующий запрос к ним повторно проверяет lifecycle объекта и не отдаёт media.
- До подтверждения удаления пользователь видит предупреждение, что внешняя площадка может продолжить публикацию, если platform cancel/delete завершится ошибкой или останется неподтверждённым.
- Позднее завершение операции не должно возвращать доступ к проекту; созданный в гонке asset остаётся недоступным и включается в lifecycle deletion.

**Критерии приёмки:**

- **AC-01:** **Дано** пользователь подтвердил удаление проекта с активным job или запланированной, но ещё не отправленной publication, **когда** система принимает запрос, **тогда** доступ немедленно закрывается, новые jobs блокируются, активные операции получают запрос отмены, а publication не передаётся платформе.
- **AC-02:** **Дано** проект логически удалён, **когда** истекает применимый `CFG-DELETION-SLA`, **тогда** система завершает физическое удаление либо фиксирует диагностируемую ошибку lifecycle job для контролируемого retry.
- **AC-03:** **Дано** YouTube уже принял будущий `PlatformNative` schedule версии проекта, **когда** пользователь подтверждает удаление проекта, **тогда** система закрывает локальный доступ, запускает platform cancel/delete attempt и показывает publication как `Cancelled` только после подтверждения YouTube.
- **AC-04:** **Дано** до удаления проекта были выданы ещё не истёкшие download URL и share link, **когда** logical delete сохранён и клиент повторно обращается по любой из ссылок, **тогда** система отказывает в выдаче media независимо от оставшегося TTL.

**Связанные FR:** `FR-PRJ-005`, `FR-RGT-010`, `FR-EXP-011`, `FR-EXP-018`, `FR-PUB-022`, `FR-PUB-025`, `FR-ADM-003`.

- **AC-02:** **Дано** дубликат создан, **когда** пользователь изменяет его метаданные или настройки, **тогда** исходный проект остаётся неизменным.

- **AC-02:** **Дано** asset относится к недоступному workspace/бренду либо не имеет применимого подтверждения прав, **когда** участник пытается выбрать его, **тогда** система запрещает использование и не раскрывает содержимое недоступного asset.

### FR-PRJ-022 — Пакетный запуск обработки проектов

**Этап:** P2 / V2  
**Актор:** Участник workspace  
**Источник:** [§ 2.2 «Вторичный сегмент»](../base/AI_Content_Factory_SaaS_Plan.md#22-вторичный-сегмент), [§ 10.4 «V2»](../base/AI_Content_Factory_SaaS_Plan.md#104-v2-ещё-1420-недель)

**Требование:** Система должна позволять уполномоченному участнику запустить поддерживаемую обработку для нескольких доступных проектов одним подтверждённым действием.

**Правила и предусловия:**

- Каждый проект сохраняет собственные source, analysis job, состояние, usage reservation и результаты.
- До запуска система показывает состав batch, недопустимые проекты и суммарный ожидаемый usage.
- Batch соблюдает entitlements и concurrency; один ошибочный проект не изменяет результаты остальных.

**Критерии приёмки:**

- **AC-01:** **Дано** выбраны несколько валидных проектов и доступен entitlement, **когда** участник подтверждает batch, **тогда** система создаёт независимо отслеживаемую analysis operation для каждого допустимого проекта и показывает общий progress.
- **AC-02:** **Дано** один проект batch завершился ошибкой, а остальные успешно, **когда** пользователь открывает batch result, **тогда** система показывает partial success и предлагает допустимый retry только для сбойного проекта.

**Связанные FR:** `FR-ANL-001`, `FR-ANL-014`, `FR-ANL-016`, `FR-BIL-002`, `FR-BIL-005`.

### FR-PRJ-023 — UX недоступного или удалённого source

**Этап:** P0 / Core MVP  
**Актор:** Пользователь  
**Источник:** [§ 8.10 «Обязательные UX-состояния»](../base/AI_Content_Factory_SaaS_Plan.md#810-обязательные-ux-состояния), [§ 9.6 «Надёжность и безопасность»](../base/AI_Content_Factory_SaaS_Plan.md#96-надёжность-и-безопасность)

**Требование:** Система должна показывать отдельное пользовательское состояние, когда запись проекта доступна, но его source asset удалён, заблокирован или недоступен по lifecycle policy.

**Правила и предусловия:**

- Система не должна возвращать broken preview/download URL или запускать новую operation, которой требуется недоступный source.
- Уже созданные immutable exports остаются доступны только если это разрешено их собственной retention/compliance policy.
- Интерфейс показывает причину и фактически доступные действия: скачать сохранившийся export, обратиться в поддержку либо удалить проект; re-upload не обещается этим требованием.

**Критерии приёмки:**

- **AC-01:** **Дано** source asset недоступен, но metadata проекта или разрешённый export сохранены, **когда** пользователь открывает проект, **тогда** система показывает состояние source unavailable/deleted, не загружает broken preview и оставляет только фактически допустимые действия.
- **AC-02:** **Дано** source asset недоступен, **когда** пользователь пытается запустить analysis, editor operation или render, зависящий от source, **тогда** система отклоняет запуск до reservation/consume и сообщает причину и следующее действие.

**Связанные FR:** `FR-PRJ-018`, `FR-RGT-008`, `FR-EXP-011`, `FR-ADM-001`.
