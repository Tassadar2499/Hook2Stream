# 06. Copy, render и export

## Назначение и границы

Документ определяет функциональные требования к генерации и редактированию copy, фиксации immutable `ClipVersion`, выполнению и контролю final render, повторному использованию идентичного результата и скачиванию одиночных или пакетных материалов. Export является полноценным обязательным сценарием Core MVP и остаётся доступен независимо от социальных интеграций.

## Функциональные требования

### FR-EXP-001 — Три редактируемых варианта copy

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий)
- **Требование:** Система должна для выбранного клипа формировать три редактируемых варианта описания — `neutral`, `emotional` и `short hook` — вместе с CTA и хэштегами.
- **Правила и предусловия:**
  - Варианты должны быть связаны с конкретным клипом и проектом релиза.
  - Пользовательская редакция сохраняется отдельно от исходного сгенерированного текста и не должна заменяться повторной генерацией без подтверждения.
  - Система не должна обещать вирусность или гарантированный performance в сгенерированном copy.
- **Критерии приёмки:**
  - **AC-01:** **Дано** выбранный клип и заполненные метаданные релиза; **Когда** пользователь запрашивает copy; **Тогда** система создаёт ровно три варианта указанных типов, каждый с редактируемыми описанием, CTA и хэштегами.
  - **AC-02:** **Дано** пользователь отредактировал вариант `emotional`; **Когда** система повторно генерирует остальные варианты; **Тогда** подтверждённая пользовательская редакция `emotional` не заменяется без явного согласия.
- **Связанные FR:** FR-EXP-002, FR-EXP-015, FR-EXP-016, FR-MET-001

### FR-EXP-002 — Копирование platform-neutral copy в clipboard

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 8.9 «Review и Export/Publish»](../base/AI_Content_Factory_SaaS_Plan.md#89-review-и-exportpublish)
- **Требование:** Система должна рядом с каждым клипом позволять скопировать выбранный platform-neutral вариант copy в clipboard.
- **Правила и предусловия:**
  - В clipboard должна попадать актуальная сохранённая редакция описания, CTA и хэштегов.
  - Копирование не должно зависеть от наличия OAuth-соединения или доступности социальной платформы.
- **Критерии приёмки:**
  - **AC-01:** **Дано** у клипа сохранён отредактированный copy; **Когда** пользователь выбирает `Скопировать описание`; **Тогда** система помещает актуальный текст в clipboard и подтверждает успешное действие.
  - **AC-02:** **Дано** социальные интеграции отключены; **Когда** пользователь копирует выбранный вариант; **Тогда** система помещает актуальный copy в clipboard без обращения к social API.
- **Связанные FR:** FR-EXP-001, FR-EXP-015, FR-EXP-020

### FR-EXP-003 — Финальный render вертикального клипа

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна создавать final video render размером 1080×1920 с видеокодеком H.264 и аудиокодеком AAC из зафиксированного composition spec.
- **Правила и предусловия:**
  - До постановки render job система должна проверить валидность composition, доступность source asset и entitlement workspace.
  - Конкретные bitrate, FPS и audio normalization задаются `CFG-EXPORT-VIDEO-BITRATE`, `CFG-EXPORT-FPS` и `CFG-EXPORT-AUDIO-NORMALIZATION` по `DEC-012`.
- **Критерии приёмки:**
  - **AC-01:** **Дано** валидный draft composition и достаточный entitlement; **Когда** пользователь запускает final render; **Тогда** система фиксирует snapshot, создаёт render job и формирует 1080×1920 H.264/AAC output.
  - **AC-02:** **Дано** source asset удалён либо composition невалидна; **Когда** пользователь пытается запустить render; **Тогда** система не резервирует неконтролируемый расход, не создаёт output и показывает конкретное исправимое предусловие.
- **Связанные FR:** FR-EDT-011, FR-EXP-007, FR-EXP-008, FR-BIL-002, FR-BIL-005

### FR-EXP-004 — Прогресс фонового render

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 8.10 «Обязательные UX-состояния»](../base/AI_Content_Factory_SaaS_Plan.md#810-обязательные-ux-состояния)
- **Требование:** Система должна выполнять render в фоне, показывать его текущее состояние и progress и продолжать обработку после закрытия страницы.
- **Правила и предусловия:**
  - Пользовательские состояния job: `Queued`, `Running`, `Succeeded`, `Failed`, `Cancelled`.
  - Повторное открытие проекта должно получать актуальное состояние durable job, а не начинать новый render.
  - Для завершённого или ошибочного job система должна показать итог и доступное следующее действие.
- **Критерии приёмки:**
  - **AC-01:** **Дано** render находится в `Running`; **Когда** пользователь закрывает и позднее открывает проект; **Тогда** render продолжается, а интерфейс показывает актуальный progress того же job.
  - **AC-02:** **Дано** render завершился ошибкой; **Когда** пользователь открывает Review/Export; **Тогда** система показывает `Failed`, понятную причину и доступное действие retry, не скрывая успешные outputs других клипов.
- **Связанные FR:** FR-ANL-014, FR-EXP-005, FR-EXP-006, FR-EXP-014, FR-EXP-019, FR-EXP-021

### FR-EXP-005 — Отмена render job

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 9.3 «Состояния»](../base/AI_Content_Factory_SaaS_Plan.md#93-состояния)
- **Требование:** Система должна позволять пользователю отменить render job, если он ещё не перешёл в терминальное состояние.
- **Правила и предусловия:**
  - Отмена должна быть идемпотентной.
  - При гонке отмены и завершения система должна сохранить ровно одно каноническое терминальное состояние и не допустить двойного результата или списания.
  - Reservation должна быть урегулирована по правилам usage ledger после подтверждения фактического результата.
- **Критерии приёмки:**
  - **AC-01:** **Дано** render job находится в `Queued`; **Когда** пользователь подтверждает отмену; **Тогда** система переводит job в `Cancelled`, не запускает media process и передаёт reservation на release/refund.
  - **AC-02:** **Дано** запрос отмены повторно доставлен после первого успешного cancel; **Когда** система обрабатывает дубликат; **Тогда** состояние остаётся `Cancelled`, новый job/output и повторная операция ledger не создаются.
- **Связанные FR:** FR-EXP-004, FR-EXP-019, FR-BIL-003, FR-BIL-004

### FR-EXP-006 — Повтор неуспешного render

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline)
- **Требование:** Система должна позволять безопасно повторить recoverable failed render без создания второй логической ClipVersion и двойного списания за один подтверждённый результат.
- **Правила и предусловия:**
  - Retry создаёт новую попытку той же логической render operation с тем же idempotency scope.
  - Невосстановимая ошибка входных данных должна требовать исправления и новой ClipVersion, а не предлагать бесконечный retry.
- **Критерии приёмки:**
  - **AC-01:** **Дано** render завершился recoverable infrastructure error до создания валидного output; **Когда** пользователь запускает retry; **Тогда** система создаёт новую попытку той же операции и при успехе связывает один валидный asset с исходной ClipVersion.
  - **AC-02:** **Дано** render завершился из-за невалидного composition field; **Когда** пользователь открывает ошибку; **Тогда** система требует исправить draft и создать новую версию вместо недетерминированного повтора прежнего snapshot.
- **Связанные FR:** FR-EXP-004, FR-EXP-007, FR-EXP-008, FR-EXP-019, FR-BIL-004

### FR-EXP-007 — Валидация final output

- **Этап:** P0 / Core MVP
- **Актор:** Фоновый обработчик
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 9.4 «Media pipeline»](../base/AI_Content_Factory_SaaS_Plan.md#94-media-pipeline), [§ 9.7 «Тестовая стратегия»](../base/AI_Content_Factory_SaaS_Plan.md#97-тестовая-стратегия)
- **Требование:** Система должна после render проверять output через media probe и признавать asset готовым только при соответствии обязательным параметрам final output.
- **Правила и предусловия:**
  - Проверяются как минимум читаемость контейнера, разрешение 1080×1920, H.264 video stream, AAC audio stream и ожидаемая длительность.
  - Невалидный или неполный output не должен становиться доступным для download/publication и не должен попадать в dedup cache как валидный.
- **Критерии приёмки:**
  - **AC-01:** **Дано** renderer создал корректный 1080×1920 H.264/AAC файл ожидаемой длительности; **Когда** media probe завершает проверку; **Тогда** система помечает asset валидным и разрешает export.
  - **AC-02:** **Дано** renderer создал повреждённый файл или output с неверным разрешением; **Когда** система выполняет проверку; **Тогда** asset не становится доступным, попытка получает `Failed`, а пользователю предлагается recoverable retry при применимости.
- **Связанные FR:** FR-EXP-003, FR-EXP-006, FR-EXP-010, FR-EXP-011

### FR-EXP-008 — Фиксация immutable ClipVersion

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 9.2 «Основные доменные сущности»](../base/AI_Content_Factory_SaaS_Plan.md#92-основные-доменные-сущности)
- **Требование:** Система должна при запуске final render фиксировать текущий mutable draft как immutable `ClipVersion`, на которую ссылаются render, export и будущая publication.
- **Правила и предусловия:**
  - Snapshot должен включать versioned composition spec и ссылки на используемые source/transcript/preset revisions.
  - После фиксации поля ClipVersion не могут изменяться; дальнейшее редактирование создаёт новый mutable draft.
  - Неуспешный render не разрешает download, но не должен изменять snapshot попытки.
- **Критерии приёмки:**
  - **AC-01:** **Дано** пользователь запускает render сохранённого draft; **Когда** запрос принят; **Тогда** система создаёт immutable ClipVersion и связывает render job именно с ней.
  - **AC-02:** **Дано** ClipVersion уже создана; **Когда** пользователь меняет crop или subtitle text; **Тогда** система изменяет новый draft, а прежняя ClipVersion и связанные с ней render/export данные остаются неизменными.
- **Связанные FR:** FR-EDT-010, FR-EDT-011, FR-EXP-009, FR-EXP-010, FR-PUB-003

### FR-EXP-009 — Новая версия после изменения composition

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export)
- **Требование:** Система должна после изменения composition создавать при следующем final render новую immutable ClipVersion, не заменяя существующую версию и её asset.
- **Правила и предусловия:**
  - Версии должны иметь устойчивые идентификаторы и быть различимы в проекте.
  - Уже скачанный, запланированный или опубликованный результат продолжает ссылаться на прежнюю версию.
- **Критерии приёмки:**
  - **AC-01:** **Дано** у клипа есть успешно отрендеренная ClipVersion, после чего пользователь изменил in/out; **Когда** пользователь запускает final render; **Тогда** система создаёт новую ClipVersion с новым composition snapshot и сохраняет прежнюю.
  - **AC-02:** **Дано** прежняя ClipVersion связана с Publication; **Когда** пользователь создаёт и рендерит новую версию; **Тогда** существующая Publication не переключается на новую версию автоматически.
- **Связанные FR:** FR-EDT-004, FR-EDT-010, FR-EXP-008, FR-EXP-010, FR-PUB-003

### FR-EXP-010 — Deduplication по composition hash

- **Этап:** P0 / Core MVP
- **Актор:** Фоновый обработчик
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 14 «Главные риски и способы снижения»](../base/AI_Content_Factory_SaaS_Plan.md#14-главные-риски-и-способы-снижения)
- **Требование:** Система должна вычислять детерминированный composition hash и переиспользовать уже валидированный render asset вместо повторной обработки идентичной composition.
- **Правила и предусловия:**
  - Hash должен учитывать все входы, способные изменить output: source revision, in/out, transform, subtitles, overlays, preset revisions и активные render parameters.
  - Переиспользовать можно только существующий валидированный asset, доступный тому же workspace по правилам isolation.
  - Cache hit должен пройти тот же entitlement/usage accounting без двойного списания фактически не выполненного compute.
- **Критерии приёмки:**
  - **AC-01:** **Дано** в workspace уже есть валидный asset с тем же composition hash; **Когда** пользователь повторяет render идентичной composition; **Тогда** система связывает ClipVersion с существующим asset и не запускает вторую media-processing operation.
  - **AC-02:** **Дано** изменён текст субтитра или версия preset; **Когда** система вычисляет hash; **Тогда** hash отличается, и asset прежней composition не переиспользуется как результат новой.
- **Связанные FR:** FR-EXP-007, FR-EXP-008, FR-EXP-009, FR-EXP-019, FR-BIL-001

### FR-EXP-011 — Скачивание одиночного MP4

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 8.9 «Review и Export/Publish»](../base/AI_Content_Factory_SaaS_Plan.md#89-review-и-exportpublish)
- **Требование:** Система должна позволять пользователю скачать валидный final MP4 конкретной ClipVersion.
- **Правила и предусловия:**
  - Download доступен только workspace с правом доступа к проекту и только для успешно валидированного asset.
  - Имя файла и TTL защищённой download URL задаются `CFG-EXPORT-FILENAME-SCHEME` и `CFG-EXPORT-DOWNLOAD-URL-TTL` по `DEC-012`.
  - URL не является безотзывным bearer-доступом: при каждом запросе файла система повторно проверяет workspace authorization и актуальный logical delete/dispute state asset.
  - Export остаётся доступен независимо от состояния или наличия social integrations.
- **Критерии приёмки:**
  - **AC-01:** **Дано** ClipVersion имеет валидный final asset; **Когда** авторизованный пользователь выбирает `Скачать MP4`; **Тогда** система выдаёт защищённую ссылку на файл этой версии со стабильным именем.
  - **AC-02:** **Дано** render находится в `Failed` либо asset не прошёл validation; **Когда** пользователь пытается скачать MP4; **Тогда** система не выдаёт повреждённый файл и показывает состояние и доступный retry.
  - **AC-03:** **Дано** пользователь получил download URL, после чего проект логически удалён либо asset стал disputed до истечения TTL; **Когда** клиент повторно запрашивает файл по этому URL; **Тогда** система отказывает в выдаче media и не полагается только на срок подписи.
- **Связанные FR:** FR-PRJ-018, FR-RGT-008, FR-EXP-007, FR-EXP-008, FR-EXP-013, FR-EDT-013

### FR-EXP-012 — Пакетный ZIP export

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна позволять пользователю скачать весь выбранный готовый пакет релиза как ZIP со стабильными именами MP4, subtitle и copy-файлов.
- **Правила и предусловия:**
  - В пакет включаются только выбранные пользователем доступные assets и актуальные сохранённые тексты.
  - Схема имён и структура ZIP задаются `CFG-EXPORT-FILENAME-SCHEME` по `DEC-012`.
  - Сбой одного render не должен удалять или делать недоступными успешно подготовленные результаты других клипов.
- **Критерии приёмки:**
  - **AC-01:** **Дано** выбран пакет клипов с валидными MP4, subtitles и copy; **Когда** пользователь выбирает `Скачать всё ZIP`; **Тогда** система формирует ZIP с выбранными файлами и стабильными именами без обращения к social APIs.
  - **AC-02:** **Дано** один клип пакета не имеет валидного render, а остальные готовы; **Когда** пользователь открывает batch export; **Тогда** система явно показывает неготовый элемент, сохраняет доступ к готовым результатам и не представляет пакет как полностью готовый.
- **Связанные FR:** FR-EXP-011, FR-EXP-013, FR-EXP-014, FR-EXP-020, FR-EXP-021

### FR-EXP-013 — Export субтитров SRT и VTT

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна экспортировать актуальные субтитры конкретной ClipVersion в форматах SRT и VTT отдельно и в составе пакетного export.
- **Правила и предусловия:**
  - Таймкоды export должны быть относительны началу готового клипа и соответствовать subtitle snapshot ClipVersion.
  - При отсутствии субтитров система должна явно показывать, что subtitle export недоступен, и не создавать пустой файл как готовый результат.
  - Имена файлов задаются `CFG-EXPORT-FILENAME-SCHEME` по `DEC-012`.
- **Критерии приёмки:**
  - **AC-01:** **Дано** ClipVersion содержит отредактированные subtitle segments; **Когда** пользователь скачивает SRT и VTT; **Тогда** оба файла содержат тот же текст и эквивалентные тайминги относительно начала клипа.

### FR-EXP-017 — Quality presets и предварительная стоимость

- **Этап:** P1 / V1
- **Актор:** Пользователь
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export)
- **Требование:** Система должна предоставлять quality presets `Preview`, `Standard` и `High` и показывать ожидаемый расход или стоимость до запуска render.
- **Правила и предусловия:**
  - Активные параметры каждого preset задаются `CFG-EXPORT-QUALITY-*` по `DEC-012`.
  - `Standard` и `High` создают exportable final output и обязаны сохранять контракт 1080×1920 H.264/AAC из `FR-EXP-003`; они могут различаться только разрешёнными quality/bitrate parameters.
  - `Preview` создаёт явно маркированный non-final asset, не является готовой `ClipVersion` для publication/clean export и проверяется по отдельному preview contract из `DEC-012`.

  - Запуск должен соблюдать entitlement и usage reservation текущего workspace.
- **Критерии приёмки:**
  - **AC-01:** **Дано** пользователю доступны все три quality preset; **Когда** он переключает `Standard` на `High`; **Тогда** система до подтверждения показывает применяемые параметры и пересчитанный ожидаемый расход.
  - **AC-02:** **Дано** выбранный preset превышает доступный entitlement; **Когда** пользователь пытается запустить render; **Тогда** система не запускает job, показывает ограничение и оставляет доступным разрешённый preset.
  - **AC-03:** **Дано** создан asset с preset `Preview`; **Когда** пользователь пытается использовать его как final export или publication payload; **Тогда** система блокирует действие, маркирует asset non-final и предлагает выполнить `Standard` либо `High` render.
- **Связанные FR:** FR-EXP-003, FR-EXP-010, FR-BIL-002, FR-BIL-005

### FR-EXP-018 — Защищённая share/review link

- **Этап:** P2 / V2
- **Актор:** Пользователь; Внешний рецензент
- **Источник:** [§ 6.6 «Copy, render и export»](../base/AI_Content_Factory_SaaS_Plan.md#66-copy-render-и-export), [§ 10.4 «V2»](../base/AI_Content_Factory_SaaS_Plan.md#104-v2-ещё-1420-недель)
- **Требование:** Система должна позволять пользователю предоставить внешнему рецензенту защищённую ссылку на конкретную ClipVersion без выдачи доступа ко всему workspace.
- **Правила и предусловия:**
  - Ссылка должна разрешать только просмотр назначенной immutable версии и явно разрешённые review-действия.
  - Authentication/identification, expiry, explicit revoke и прочие правила ссылки определяются `DEC-016`.

  - **AC-02:** **Дано** ссылка отозвана или недействительна; **Когда** внешний рецензент обращается по ней; **Тогда** система отказывает в доступе без раскрытия project/workspace data.
  - **AC-03:** **Дано** внешняя ссылка была валидна, после чего проект удалён либо версия стала disputed; **Когда** рецензент повторно открывает прежнюю ссылку; **Тогда** система не отдаёт preview/media и не раскрывает дополнительные сведения об объекте.

### FR-EXP-019 — Идемпотентность render operations

- **Этап:** P0 / Core MVP
- **Актор:** Фоновый обработчик
- **Источник:** [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp), [§ 9.3 «Состояния»](../base/AI_Content_Factory_SaaS_Plan.md#93-состояния), [§ 9.6 «Надёжность и безопасность»](../base/AI_Content_Factory_SaaS_Plan.md#96-надёжность-и-безопасность)
- **Требование:** Система должна идемпотентно обрабатывать restart, retry и duplicate delivery render operation, не создавая двойной asset или повторное списание.
- **Правила и предусловия:**
  - Render operation должна иметь idempotency key, связывающий ClipVersion, composition hash и логическую операцию.

- **Критерии приёмки:**
  - **AC-01:** **Дано** worker перезапущен после создания asset, но до подтверждения job; **Когда** команда доставлена повторно; **Тогда** система распознаёт уже созданный валидный результат, завершает исходную операцию и не создаёт второй asset или consume.
  - **AC-02:** **Дано** одна и та же render-команда доставлена обработчику дважды; **Когда** обе доставки используют один idempotency key; **Тогда** система создаёт не более одного валидного asset и одной канонической usage operation.
- **Связанные FR:** FR-EXP-004, FR-EXP-005, FR-EXP-006, FR-EXP-010, FR-BIL-004

### FR-EXP-021 — Изоляция сбоев отдельных render

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 7.3 «Definition of Done MVP»](../base/AI_Content_Factory_SaaS_Plan.md#73-definition-of-done-mvp), [§ 9.3 «Состояния»](../base/AI_Content_Factory_SaaS_Plan.md#93-состояния)
- **Требование:** Система должна изолировать render каждого клипа так, чтобы сбой одной операции не удалял, не изменял и не блокировал успешные результаты других клипов проекта.
- **Правила и предусловия:**
  - Состояние проекта не заменяет состояния отдельных render jobs и ClipVersion.

  - **AC-02:** **Дано** пользователь запускает retry сбойного render; **Когда** новая попытка переходит в `Running`; **Тогда** состояния и assets уже успешных render не изменяются.

### FR-EXP-022 — Пакетный запуск render

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна позволять пользователю одним подтверждённым действием запустить final render нескольких выбранных клипов проекта.

  - **AC-02:** **Дано** одна операция batch завершилась ошибкой, а остальные успешно; **Когда** пользователь открывает результат batch; **Тогда** система показывает partial success, оставляет успешные версии доступными и предлагает retry только для сбойной операции.
