# 05. Candidate Review и Clip Editor

## Назначение и границы

Документ определяет функциональные требования к просмотру и отбору кандидатов, лёгкому монтажу вертикального клипа, субтитрам, safe zones, autosave и согласованности preview с финальным render. Core MVP предоставляет полный редактор только в desktop web; обязательный mobile web subset зафиксирован отдельно.

## Функциональные требования

### FR-EDT-001 — Карточка кандидата в Candidate Review

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.7 «Candidate Review»](../base/AI_Content_Factory_SaaS_Plan.md#87-candidate-review)
- **Требование:** Система должна показывать каждого доступного кандидата в визуальной карточке с вертикальным preview, временными границами, длительностью, типом, объяснением, lyric excerpt при его наличии, confidence, предупреждениями и действиями выбора, изменения и отклонения.
- **Правила и предусловия:**
  - Ручной кандидат должен отображаться в той же сетке с явной отметкой источника `manual`.
  - Предупреждения должны отражать как минимум низкую уверенность текста и необходимость проверки crop, когда соответствующий риск сохранён анализом.
  - Псевдоточная оценка вирусности не должна отображаться.
- **Критерии приёмки:**
  - **AC-01 — Полная карточка автоматического кандидата**
    - **Дано:** analysis job создал кандидата с lyrics, explanation, confidence и crop warning;
    - **Когда:** пользователь открывает Candidate Review;
    - **Тогда:** карточка показывает preview, таймкоды, длительность, тип, объяснение, lyric excerpt, confidence, предупреждение и действия `Выбрать`, `Изменить`, `Отклонить`.
  - **AC-02 — Карточка ручного кандидата без lyrics**
    - **Дано:** пользователь создал ручной кандидат в проекте без текста;
    - **Когда:** система отображает сетку кандидатов;
    - **Тогда:** карточка показывает источник `manual` и доступные данные, не создавая пустой lyric excerpt или AI-confidence.
- **Связанные FR:** FR-ANL-009, FR-ANL-010, FR-EDT-002, FR-EDT-003

### FR-EDT-002 — Фильтрация кандидатов

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor)
- **Требование:** Система должна позволять пользователю фильтровать кандидатов по типу момента, длительности и состоянию пользовательского выбора.
- **Правила и предусловия:**
  - Состояния пользовательского выбора: `Suggested`, `Selected`, `Rejected`.
  - Фильтр не должен удалять кандидатов или менять сохранённое состояние выбора.
  - Границы фильтра длительности используют активную конфигурацию `CFG-CANDIDATE-*`, определённую `DEC-002`.
- **Критерии приёмки:**
  - **AC-01 — Комбинация фильтров**
    - **Дано:** в проекте есть кандидаты разных типов, длительностей и состояний;
    - **Когда:** пользователь выбирает тип `chorus`, допустимый поддиапазон длительности и состояние `Selected`;
    - **Тогда:** система показывает только кандидатов, одновременно удовлетворяющих всем выбранным условиям.
  - **AC-02 — Сброс фильтров**
    - **Дано:** активный фильтр скрывает часть кандидатов;
    - **Когда:** пользователь сбрасывает фильтры;
    - **Тогда:** система снова показывает все доступные кандидаты с неизменёнными состояниями выбора.
- **Связанные FR:** FR-EDT-001, FR-EDT-003, FR-ANL-008

### FR-EDT-003 — Выбор и отклонение кандидата

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 5 «Сквозной пользовательский сценарий»](../base/AI_Content_Factory_SaaS_Plan.md#5-сквозной-пользовательский-сценарий)
- **Требование:** Система должна позволять пользователю перевести предложенный кандидат в состояние `Selected` или `Rejected` и сохранить это решение как feedback.
- **Правила и предусловия:**
  - Пользователь может изменить прежнее решение; система хранит актуальное состояние и событие его изменения для product analytics.
  - `Selected` в P0 означает пользовательский выбор кандидата и не является командным состоянием `Approved` из P2 approval flow.
  - Отклонение кандидата не должно удалять его из проекта.
- **Критерии приёмки:**
  - **AC-01 — Выбор кандидата**
    - **Дано:** кандидат находится в состоянии `Suggested`;
    - **Когда:** пользователь нажимает `Выбрать`;
    - **Тогда:** система сохраняет состояние `Selected`, фиксирует feedback и делает кандидат доступным для редактирования.
  - **AC-02 — Отклонение с возможностью возврата**
    - **Дано:** кандидат находится в состоянии `Selected`;
    - **Когда:** пользователь выбирает `Отклонить`, а затем возвращает его в `Selected`;
    - **Тогда:** система сохраняет оба события, показывает актуальное состояние `Selected` и не теряет данные кандидата.
- **Связанные FR:** FR-EDT-001, FR-EDT-002, FR-ANL-013

### FR-EDT-004 — Корректировка границ клипа

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна в desktop Clip Editor позволять пользователю изменять in/out границы выбранного клипа на timeline с waveform, song-section markers и lyric markers.
- **Правила и предусловия:**
  - Границы должны оставаться внутри длительности исходного asset, образовывать положительную длительность и соответствовать активным `CFG-CANDIDATE-*` из `DEC-002`.
  - При перемещении границы система должна предлагать привязку к ближайшему музыкальному или lyric marker; пользователь сохраняет возможность установить другую валидную позицию.
- **Критерии приёмки:**
  - **AC-01 — Привязка к marker**
    - **Дано:** рядом с изменяемой out-границей есть конец lyric line и музыкальная граница;
    - **Когда:** пользователь перемещает out handle к marker;
    - **Тогда:** система предлагает точную привязку, обновляет длительность preview и сохраняет выбранную валидную границу в draft composition.
  - **AC-02 — Отклонение невалидного интервала**
    - **Дано:** пользователь пытается установить границы вне исходника или получить недопустимую длительность;
    - **Когда:** пользователь завершает изменение;
    - **Тогда:** система не сохраняет невалидные границы и сообщает применённое ограничение.
- **Связанные FR:** FR-ANL-003, FR-ANL-010, FR-EDT-010, FR-EDT-011

### FR-EDT-005 — Режим кадрирования Fit с размытым фоном

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна предоставлять режим `9:16 Fit + blurred background`, сохраняющий весь широкий исходный кадр на вертикальном canvas и заполняющий свободную область размытой копией кадра.
- **Правила и предусловия:**
  - Для широкого исходника этот режим должен быть доступен как рекомендуемый вариант.
  - Пропорции foreground-видео не должны искажаться.
  - Параметры режима должны сохраняться в draft composition и применяться одинаково в preview и final render.
- **Критерии приёмки:**
  - **AC-01 — Широкий исходник**
    - **Дано:** пользователь редактирует широкий исходник, включая ультраширокую композицию;
    - **Когда:** пользователь выбирает `Fit + blurred background`;
    - **Тогда:** preview показывает весь исходный кадр без обрезки и заполняет вертикальный canvas размытой копией фона.
  - **AC-02 — Сохранение режима**
    - **Дано:** пользователь выбрал Fit и сохранил draft;
    - **Когда:** пользователь повторно открывает клип;
    - **Тогда:** система восстанавливает тот же режим и его параметры без изменения композиции.
- **Связанные FR:** FR-ANL-005, FR-EDT-007, FR-EDT-011, FR-EXP-003

### FR-EDT-006 — Режим кадрирования Fill с ручным pan и zoom

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна предоставлять режим `9:16 Fill`, заполняющий вертикальный canvas и позволяющий пользователю вручную смещать и масштабировать исходное изображение.
- **Правила и предусловия:**
  - Ручное позиционирование должно работать независимо от наличия лица и поддерживать visual focus для AI/anime-клипов.
  - Система не должна позволять сохранить положение, оставляющее незаполненную область canvas в режиме Fill.
  - Pan/zoom должны сохраняться в draft composition и применяться одинаково в preview и final render.
- **Критерии приёмки:**
  - **AC-01 — Ручной visual focus**
    - **Дано:** важный объект широкого кадра расположен у края и не является лицом;
    - **Когда:** пользователь выбирает Fill и изменяет pan/zoom;
    - **Тогда:** система обновляет preview, сохраняет объект в выбранной области вертикального кадра и записывает параметры в composition.
  - **AC-02 — Недопустимое положение**
    - **Дано:** текущий zoom недостаточен для заполнения canvas;
    - **Когда:** пользователь пытается сохранить pan, создающий пустую область;
    - **Тогда:** система ограничивает трансформацию валидным диапазоном и не сохраняет незаполненный canvas.
- **Связанные FR:** FR-ANL-005, FR-EDT-007, FR-EDT-011, FR-EXP-003

### FR-EDT-007 — Отображение и версионирование safe zones

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна накладывать на editor preview safe-zone overlay выбранного platform preset и сохранять идентификатор версии preset в composition.
- **Правила и предусловия:**
  - Safe zones являются вспомогательным overlay редактора и не должны попадать в final render.
  - Обновление platform preset не должно молча изменять уже зафиксированную ClipVersion.
  - При открытии draft со старой версией preset система должна сохранить её либо явно предложить пользователю обновление.
- **Критерии приёмки:**
  - **AC-01 — Overlay в редакторе**
    - **Дано:** для выбранной платформы доступен versioned safe-zone preset;
    - **Когда:** пользователь включает safe zones;
    - **Тогда:** система показывает overlay поверх preview, сохраняет версию preset и не встраивает overlay в изображение клипа.
  - **AC-02 — Обновление preset**
    - **Дано:** после сохранения ClipVersion опубликована новая версия safe-zone preset;
    - **Когда:** пользователь открывает существующую ClipVersion;
    - **Тогда:** система продолжает использовать зафиксированную версию и не изменяет immutable composition автоматически.
- **Связанные FR:** FR-EDT-005, FR-EDT-006, FR-EDT-011, FR-EXP-008

### FR-EDT-008 — Редактирование текста и таймингов субтитров

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна позволять пользователю редактировать текст и тайминги субтитров выбранного клипа до final render.
- **Правила и предусловия:**
  - Изменения субтитров клипа сохраняются как clip-specific overrides над зафиксированной base transcript revision и не должны незаметно изменять исходный transcript проекта.
  - Preview и final render используют один resolved subtitle snapshot по правилам `FR-LYR-010`.
  - Тайминги должны находиться внутри in/out интервала клипа и не иметь отрицательной длительности.
  - Клип может быть сохранён и отрендерен без субтитров.
- **Критерии приёмки:**
  - **AC-01 — Исправление распознанного текста**
    - **Дано:** subtitle segment содержит ошибку распознавания;
    - **Когда:** пользователь исправляет текст и сохраняет draft;
    - **Тогда:** preview показывает исправленный текст, а draft composition хранит редакцию для будущего render и subtitle export.
  - **AC-02 — Невалидный тайминг**
    - **Дано:** пользователь задаёт окончание subtitle segment за out-границей клипа;
    - **Когда:** система валидирует изменение;
    - **Тогда:** система не сохраняет невалидный тайминг и показывает допустимую границу.
- **Связанные FR:** FR-LYR-010, FR-ANL-003, FR-EDT-009, FR-EDT-010, FR-EXP-013

### FR-EDT-009 — Оформление субтитров и три preset Core MVP

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 7.1 «В Core MVP входит»](../base/AI_Content_Factory_SaaS_Plan.md#71-в-core-mvp-входит)
- **Требование:** Система должна предоставлять три проверенных subtitle preset и позволять пользователю изменять позицию, размер и цвет субтитров.
- **Правила и предусловия:**
  - Каталог P0 должен содержать ровно три доступных preset, как установлено исходным планом; их визуальные спецификации являются частью design system, а не новым числовым решением FR.
  - Позиция субтитров должна проверяться относительно canvas и выбранных safe zones.
  - Стиль сохраняется в draft composition.
- **Критерии приёмки:**
  - **AC-01 — Применение preset**
    - **Дано:** пользователь открыл клип с субтитрами;
    - **Когда:** пользователь выбирает один из трёх preset и меняет размер и цвет;
    - **Тогда:** система обновляет preview и сохраняет выбранный preset и overrides в composition.
  - **AC-02 — Проверка позиции**
    - **Дано:** пользователь перемещает субтитры за пределы вертикального canvas;
    - **Когда:** система валидирует позицию;
    - **Тогда:** система не сохраняет недоступное положение и показывает допустимую область с учётом safe-zone overlay.
- **Связанные FR:** FR-EDT-007, FR-EDT-008, FR-EDT-011, FR-EXP-003

### FR-EDT-010 — Autosave mutable draft composition

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна автоматически сохранять изменения границ, кадра, субтитров и текста в mutable draft composition и показывать пользователю состояние сохранения.
- **Правила и предусловия:**
  - Autosave не создаёт immutable ClipVersion; версия фиксируется только при запуске final render.
  - Mutable draft имеет server revision; autosave передаёт revision, на которой основана правка, и применяет optimistic concurrency control.
  - Stale autosave из другой вкладки или от другого `Editor` не должен молча перезаписывать более новую server revision: система сохраняет несинхронизированные локальные изменения и показывает явный конфликт с действиями reload/reapply; live collaborative editing не обещается.
  - Пользователь не должен терять подтверждённые autosave-изменения после закрытия или повторного открытия страницы.
  - При ошибке сохранения система должна сохранить локальное несинхронизированное состояние, явно сообщить об ошибке и предоставить повтор.
- **Критерии приёмки:**
  - **AC-01 — Восстановление draft**
    - **Дано:** пользователь изменил in/out, crop и subtitle style, а система подтвердила autosave;
    - **Когда:** пользователь закрывает и повторно открывает editor;
    - **Тогда:** система восстанавливает все подтверждённые изменения из того же mutable draft.
  - **AC-02 — Ошибка autosave**
    - **Дано:** сохранение временно завершилось recoverable error;
    - **Когда:** пользователь продолжает редактирование;
    - **Тогда:** система не сообщает ложный статус `Сохранено`, сохраняет несинхронизированные изменения для повтора и не заменяет их более старым server state без предупреждения.
  - **AC-03 — Конфликт ревизий**
    - **Дано:** два редактора открыли revision R1, первый сохранил R2, а второй отправляет stale autosave на базе R1;
    - **Когда:** система проверяет revision второго запроса;
    - **Тогда:** система не перезаписывает R2, возвращает явный conflict и сохраняет локальные изменения второго редактора для reload/reapply.
- **Связанные FR:** FR-EDT-004, FR-EDT-008, FR-EDT-011, FR-EXP-008

### FR-EDT-011 — Единый composition spec для preview и final render

- **Этап:** P0 / Core MVP
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 8.8 «Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#88-clip-editor)
- **Требование:** Система должна строить proxy-preview и final render из одного и того же versioned composition spec.
- **Правила и предусловия:**
  - Composition spec должен включать как минимум source/in-out, canvas/crop transform, subtitle content/timings/style и ссылки на версии используемых preset.
  - Различие разрешения или качества proxy и final output не должно менять композиционные решения.
  - Неподдерживаемое или неполное поле composition должно блокировать final render с понятной ошибкой, а не игнорироваться молча.
- **Критерии приёмки:**
  - **AC-01 — Композиционная эквивалентность**
    - **Дано:** preview построен из draft с Fill, pan/zoom и субтитрами;
    - **Когда:** пользователь запускает final render без изменения draft;
    - **Тогда:** renderer получает snapshot того же composition spec, и кадрирование, тайминги и оформление соответствуют preview.
  - **AC-02 — Невалидная composition**
    - **Дано:** composition ссылается на отсутствующий subtitle preset или содержит невалидную transform;
    - **Когда:** пользователь запускает final render;
    - **Тогда:** система не начинает расходный render и сообщает, какой параметр необходимо исправить.
- **Связанные FR:** FR-EDT-005, FR-EDT-006, FR-EDT-007, FR-EDT-008, FR-EXP-003, FR-EXP-008

### FR-EDT-012 — Маркировка proxy-preview и параметров final output

- **Актор:** Пользователь

  - Preview не должен маркироваться как готовый final asset.

    - **Дано:** отдельный эффект или шрифт не может быть достоверно показан в proxy;
    - **Когда:** система отображает preview;
    - **Тогда:** система предупреждает о различии и не утверждает полную визуальную идентичность этого элемента.

### FR-EDT-014 — Smart reframe

- **Этап:** P1 / V1
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 10.3 «V1 после подтверждения Core MVP»](../base/AI_Content_Factory_SaaS_Plan.md#103-v1-после-подтверждения-core-mvp-ещё-1218-недель)
- **Требование:** Система должна предлагать smart reframe на основе трекинга лиц, объектов и visual saliency, включая режим работы для сцен без лиц.
- **Правила и предусловия:**
  - Smart reframe является предлагаемой автоматической transform и не должен запрещать последующую ручную корректировку pan/zoom.
  - Результат smart reframe должен сохраняться в composition как редактируемые параметры.
- **Критерии приёмки:**
  - **AC-01 — Сцена с лицом**
    - **Дано:** в выбранном сегменте обнаружено движущееся лицо;
    - **Когда:** пользователь применяет smart reframe;
    - **Тогда:** система предлагает transform, удерживающую лицо в вертикальной композиции, и позволяет изменить её вручную.
  - **AC-02 — AI/anime-сцена без лиц**
    - **Дано:** в сегменте нет распознанных лиц, но обнаружен визуально значимый объект;
    - **Когда:** пользователь применяет smart reframe;
    - **Тогда:** система использует object/saliency признаки либо сообщает об отсутствии уверенного focus и оставляет доступным ручной Fill+pan.
- **Связанные FR:** FR-ANL-005, FR-EDT-006, FR-EDT-010

- **Требование:** Система должна позволять сохранять и повторно применять привязанные к артисту templates canvas, субтитров и CTA.

  - Template должен быть изолирован в workspace и связан с конкретным ArtistProfile, если он задан.

### FR-EDT-016 — Undo, redo и история рабочих версий

- **Этап:** P1 / V1
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor)
- **Требование:** Система должна позволять отменять и повторять изменения текущего draft и восстанавливать сохранённую рабочую версию без предоставления полноценного multi-track NLE.
- **Правила и предусловия:**
  - Undo/redo применяется к изменениям composition текущего draft и не изменяет immutable ClipVersion.
  - Восстановление исторической рабочей версии создаёт новое текущее состояние draft, сохраняя саму историю.
- **Критерии приёмки:**
  - **AC-01 — Undo и redo**
    - **Дано:** пользователь последовательно изменил pan и subtitle color;
    - **Когда:** пользователь выполняет undo, а затем redo;
    - **Тогда:** система отменяет и повторно применяет последнее изменение в ожидаемом порядке и обновляет preview.
  - **AC-02 — Восстановление прежней рабочей версии**
    - **Дано:** в истории есть сохранённая рабочая версия до серии изменений;
    - **Когда:** пользователь восстанавливает эту версию;
    - **Тогда:** система делает её содержимое текущим draft и не изменяет ранее отрендеренные ClipVersion.
- **Связанные FR:** FR-EDT-010, FR-EDT-011, FR-EXP-008, FR-EXP-009

### FR-EDT-017 — Karaoke highlighting

- **Этап:** P1 / V1
- **Актор:** Пользователь

- **Связанные FR:** FR-LYR-006, FR-LYR-008, FR-EDT-008, FR-EDT-009, FR-EDT-011

### FR-EDT-018 — Условный multi-track/B-roll editor

- **Этап:** Later
- **Актор:** Пользователь
- **Источник:** [§ 6.5 «Candidate Review и Clip Editor»](../base/AI_Content_Factory_SaaS_Plan.md#65-candidate-review-и-clip-editor), [§ 7.2 «В Core MVP не входит»](../base/AI_Content_Factory_SaaS_Plan.md#72-в-core-mvp-не-входит)
- **Требование:** Система должна предоставлять multi-track/B-roll editor только после отдельного подтверждения спроса на замену внешнего монтажного инструмента и явного включения функции для workspace.
- **Правила и предусловия:**
  - Функция не входит в P0, P1 или обязательства P2 и по умолчанию не должна отображаться как доступная.
  - Gate считается пройденным только после отдельного продуктового решения, основанного на данных о готовности пользователей заменить CapCut, а не только подготовить short.
  - Недоступность multi-track editor не должна ограничивать Core-сценарий лёгкой правки, render и export.
- **Критерии приёмки:**
  - **AC-01:** **Дано** отдельное подтверждение спроса отсутствует или feature flag выключен; **Когда** пользователь открывает Clip Editor; **Тогда** система не показывает рабочие multi-track/B-roll действия и сохраняет весь Core editor доступным.
  - **AC-02:** **Дано** продуктовый gate формально пройден и функция включена для workspace; **Когда** авторизованный пользователь открывает Clip Editor; **Тогда** система предоставляет multi-track/B-roll возможности только в разрешённом workspace, не изменяя прежние immutable ClipVersion.
- **Связанные FR:** FR-EDT-010, FR-EDT-011, FR-EXP-008, FR-EXP-009
